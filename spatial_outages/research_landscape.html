The V1 algorithm

Six decisions. No model training.

Each step answers one question and can be reproduced from stored evidence.

Is the whole CSP down?

If the upstream incident is provider-wide, retain it for audit and stop local polygon creation.

wide → exit local flow

Which failures connect?

Add an edge only when two failed devices are geographically close and their down intervals overlap.

near AND concurrent

What is one event?

Each connected component is a candidate event. No fixed number of clusters and no H3 border.

component = membership

Who belongs in its denominator?

Assign every time-valid local device to one candidate only. Missing telemetry remains UNKNOWN.

no double counting

Is the evidence strong enough?

Keep the event only when the local population and affected share both clear the V1 gates.

eligible ≥ 10; affected ≥ 75%

How do we describe it?

Draw the polygon, compare CSP states, and stitch later versions without rewriting source history.

inferred domain, not cause
✦

The non-negotiable rule

Devices decide membership. The polygon only visualises membership. Overlapping polygons must never merge two outage groups.

    What fourteen papers actually change

    The literature strengthens the guardrails—not the machinery.

    The exact pipeline is not reproduced by one paper. The closest work supports individual choices and warns against premature complexity.

    Use now

    • Explicit UNKNOWN state
    • Separate detection from cause
    • Preserve source lineage

    • Component bridge chaining
    • False merge and split rate
    • Stitching stability
    • Detection delay
    Defer

    • Shared change-point models
    • Spectral graph detection
    • Dynamic graph ML

    Paper-by-paper evidence

    Scope decision

    What we build first—and what waits.

    A deterministic V1 is enough to test whether device-first grouping beats the current H3 baseline.

    Build now

    Small, auditable V1

    • Consume TFF member intervals and device inventory
    • Exclude CSP-wide events from local grouping
    • Build distance + time-overlap components
    • Apply unique denominator ownership and evidence gates
    • Draw versioned polygons and conservative domain labels
    • Log every threshold and decision
    Only after replay

    Add when evidence demands it

    • Statistical shared-change detection
    • Automatic component bridge splitting
    • Spectral or learned graph anomaly models
    • Supervised physical-cause classification
    • External weather, search, or active-probe inputs
    The next proof: replay the same labelled historical incidents through H3 and device-first V1; compare event precision/recall, false merges/splits, delay, stability, and UNKNOWN rate. Until then, “better than H3” is a hypothesis.

    Evidence boundary: 13 full papers and one abstract-only source were inspected. All cause labels shown here are inferred domains, not confirmed physical causes.
