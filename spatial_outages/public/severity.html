How device downtime becomes an attributed outage

A device going down is raw evidence. The engine first exits CSP-wide failures, then groups the remaining spatially connected devices into fluid polygons for local attribution.

Two decision grainsCSP × time window first. Fluid polygon for everything that remains.

Problem

Individual devices fail for many unrelated reasons. A CSP-wide failure should not create hundreds of false local polygons, while static cells create artificial borders for the failures that remain.

Requirements

Use the real sourcedevice_id is the atomic evidence unit.
Use coordinatesEvery active device needs one trusted location from the existing source flow.

Require a complete baselineDo not infer ISP / OLT when the active CSP denominator is incomplete.
Grow the shapeBFS joins spatial neighbors with overlapping downtime.
Require scaleA candidate polygon needs at least 10 eligible devices.
Require impactAt least 75% of eligible devices must be affected.
Preserve evidenceKeep every source outage ID and member device.

Definition of an outage polygon

After CSP-wide exits are removed, a fluid candidate becomes an outage polygon only when both the population and affected-share gates pass.

Eligible devices ≥ 10Distinct remaining active devices whose coordinates fall inside the candidate geometry.
AND
Affected share ≥ 75%Affected share is distinct affected devices divided by eligible devices. The boundary is inclusive.
10 is the polygon minimum9 eligible devices can never produce an outage polygon.
75% is inclusive8 of 10 is 80% and qualifies; 7 of 10 does not.
Concurrency supports groupingDowntime overlap joins related devices but does not replace the 75% gate.

Grow fluid polygons after the CSP-wide exit

BFS sees only the remaining device universe and follows spatially connected concurrent failures.

Device graph → connected component → outage polygon

Each remaining active device is a located node. Devices belonging to an exited CSP-window are excluded from both BFS seeds and the polygon denominator. Downtime overlap determines whether a spatial edge can be crossed.

Example fluid component

Polygon P-001

Seed one remaining affected deviceSkip any device in an exited CSP-window or already visited in the current attribution window.
Read spatial neighborsDerive the versioned adjacency graph from device latitude and longitude; no new source table is introduced.
Cross only valid edgesThe neighbor is affected and its downtime interval overlaps the component's event interval.
Close the componentWhen the queue is empty, retain the visited devices and all source outage IDs.
Create and test the polygonBuild geometry, count remaining active devices inside it, calculate affected share, then require at least 10 devices and 75% affected.
Fluid behaviorThe polygon can expand, split, contract, merge, or close as device states change.
Geometry safetyVersion the neighbor distance, hull method, and buffer. Validate them against denominator inflation.
Filter safetyKeep exited devices for audit, but exclude them from both the downstream numerator and denominator.
active_devices = active CUSTOMER_V_2 devices with CSP and location
down_devices = active devices concurrently down at evaluation_time
excluded_csp_windows = empty set

FOR EACH csp_id IN active_devices:
  csp_eligible = active_devices for csp_id
  csp_down = down_devices for csp_id
  csp_down_share = COUNT(csp_down) / COUNT(csp_eligible)

  IF CSP_BASELINE_IS_COMPLETE(csp_id)
     AND csp_down_share >= 0.80:
    EMIT ISP_OLT with csp_id, counts, share, time, and source outage IDs
    ADD csp_id + evaluation_time TO excluded_csp_windows

remaining_active_devices = active_devices outside excluded_csp_windows
affected_nodes = down_devices outside excluded_csp_windows
visited = empty set

FOR EACH seed IN affected_nodes:
  IF seed IN visited:
    CONTINUE
  queue = [seed]
  component = empty set

  WHILE queue is not empty:
    current = POP_FRONT(queue)
    IF current IN visited:
      CONTINUE
    ADD current TO visited AND component

    FOR EACH neighbor IN SPATIAL_NEIGHBORS(current):
      IF neighbor IN affected_nodes
         AND DOWNTIME_OVERLAPS(neighbor, component)
         AND neighbor NOT IN visited:
        APPEND neighbor TO queue

  geometry = CONCAVE_HULL(component coordinates)
  eligible_devices = remaining active devices inside geometry
  affected_devices = affected devices inside geometry
  affected_share = affected_devices / eligible_devices

  IF eligible_devices >= 10 AND affected_share >= 0.75:
    EMIT outage_polygon
  ELSE:
    EMIT noise_candidate

Apply the CSP-wide rule before polygon rules

The top-down contract prevents a CSP-wide event from fragmenting into misleading local polygons.

Ordered outage attribution contract

CSP_WIDE_DEVICE_SHARE = 0.80First ISP / OLT filter against the complete active CSP baseline.
MIN_ELIGIBLE_DEVICES = 10Inclusive polygon population gate.
MIN_AFFECTED_SHARE = 0.75Inclusive polygon impact gate.
EDGE_OVERLAP > 0Grouping evidence only; not a qualification alternative.
OrderIfThenEvidence retained
0At least 80% of one CSP's complete active-device baseline is concurrently down at the evaluation time.ISP / OLTCSP ID, evaluation time, eligible and down device IDs, share, and source outages. Exclude the CSP-window before BFS.
1A remaining candidate has fewer than 10 eligible devices, or its affected share is below 75%.NOISEEligible count, affected count, affected share, and failed gate.
2Two or more comparable CSPs are affected together inside one remaining polygon.POWER / SHARED AREACSP-level device counts, shares, and overlapping intervals inside the polygon.
3The same multi-CSP pattern appears across multiple separated outage polygons in one event.REGIONALPolygon IDs, geometries, compared CSPs, and event timing.
4One CSP is affected inside the polygon and at least one other eligible CSP is observed healthy there.FIBRE / LOCAL CSPAffected CSP evidence and healthy same-polygon comparison CSP evidence.
5The polygon qualifies but the required cross-CSP comparison is missing or conflicting.UNKNOWNAvailable evidence and the exact missing comparison.

Safety boundary: `FIBRE`, `POWER`, and `ISP / OLT` are inferred failure domains. Confirm the physical cause with OLT alarms, power telemetry, tickets, or field evidence.

NOISEA remaining candidate fails the polygon population or impact gate.
POWER / SHARED AREAMultiple CSPs fail together inside one polygon.
REGIONALThe shared multi-CSP pattern spans separated polygons.
FIBRE / LOCAL CSPOne CSP fails while another CSP is healthy inside the polygon.

5

Dry-run every outage outcome

The first run is CSP × time window; the remaining runs use fluid polygons.

How to read the dry runs

  • CSP-wide first: concurrently down devices divided by the CSP's complete active-device baseline.
  • Exit: a CSP at or above 80% is published as ISP / OLT before BFS.
  • Eligible polygon devices: remaining active devices inside the candidate geometry.
  • Affected polygon devices: remaining devices with downtime evidence in the attribution window.
  • Grouping: overlapping downtime lets BFS join spatial-neighbor devices.
  • Qualification: at least 10 eligible devices and at least 75% affected.
  • CSP Alpha: provider being evaluated.
  • CSP Beta: comparison provider in the same analysis scope or remaining polygon.

Implement and validate the new grain

The current classifier is not yet polygon-native; these are the concrete changes required.

Decided

Top-down contract

  • Device is the raw grain
  • CSP × time window is checked first
  • At least 80% CSP devices down exits as ISP / OLT
  • Exited CSP-window devices are excluded from both downstream counts
  • Remaining polygons require 10 devices and 75% affected

Required implementation

Still needed

  • Calculate complete CSP active baselines before BFS
  • Export recovery intervals from the same OUTAGE_MEMBER_V3 source when overlap grouping needs them
  • Validate device coordinates from T_ADDRESS
  • Build and version spatial adjacency
  • Implement BFS and geometry creation on the remaining devices

Validation and safety

  • Back-test the 80% CSP-device, 10-device polygon, and 75% affected-share boundaries.
  • Measure CSP baseline completeness and local events masked by the CSP-wide exit.
  • Measure recall, false polygons, detection delay, split/merge stability, and Unknown rate.
  • Keep exact source outage and member device lineage for both decision grains.
  • Do not claim confirmed fibre, power, or OLT cause without operational evidence.

Next step: update the data export and Python engine to publish CSP-window exits and polygon results separately. Until that happens, this HTML is the target design, not a description of current runtime behavior.
